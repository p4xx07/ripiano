## Current checkpoint

- The foundation includes owner sign-in, durable upload/OCR/search, PWA capture paths, native Android debug scanner, phrase-based tag/sender/type filing, physical stickers and locations, Telegram and watched-folder inputs, scoped agent MCP grants, scheduled NAS backup output, and a clean-stack restore drill.
- The Library has filters, saved searches, contextual snippets, field-qualified search, signed-cursor sorting, and owner-scoped bulk tagging/sender/type filing. Bulk manual corrections survive later automatic filing. The API now requires a full PostgreSQL text-search match before ranking results, and Library cards show manual tags first.
- Documents now have dated searchable notes and a per-document OCR rebuild action. The reprocess browser journey verifies that original bytes remain identical after rebuilding the searchable PDF.
- Reversible Trash now preserves originals, notes, tags, physical stickers, and history. Search, downloads, needs-action views, bulk edits, and MCP access exclude trashed documents; sticker lookup gives a restore notice. The PWA has an explicit confirmation and a responsive Trash/Restore page. Processing documents cannot enter Trash until OCR finishes. There is no permanent purge yet.
- Paper copies can now be marked Missing/Found. The sticker stays stable, the last known location remains visible during a missing report, history records both transitions, and a missing copy cannot be moved until found.
- Shelves and boxes now have stable printable `L-` QR labels. Scanning a location shows active paper copies there and in nested locations, with paged results and missing-copy warnings. Location-label lookup is owner scoped and excludes trashed documents.
- Related documents now have reciprocal links created from the document panel. The API enforces owner and Trash isolation; a relationship hidden during Trash reappears on Restore. The panel searches the existing Library and can open or unlink either side.
- A single document can now be exported as a portable ZIP containing the original, optional searchable PDF and OCR text, and a readable JSON manifest with checksums and metadata. The API checks the preserved original against its archive record before delivering the ZIP. Full archive export/import remains open.
- Typed custom fields support text, number, date, and yes/no values. The document panel shows filled fields and lets users choose an unused field. Library search finds values through ordinary text, `field:"Name=value"`, or a visual field/value filter. Saved searches preserve that filter. The panel can rename field definitions and delete unused ones; values and saved searches protect a field from deletion. Custom values are in the portable export. Type changes and range filters remain open.
- Reclassification and backup tasks use a `maintenance` Celery queue and worker; new uploads and retries use the separate `celery` processing queue. Both local and Portainer Compose examples include the new service.
- The latest feature checkpoints include Trash/Restore, missing/found paper-copy status, scannable shelf/box labels, related-document links, single-document ZIP export, typed custom fields, and visual custom-field filters with saved-search persistence and definition management. The local API suite passed **53 tests** with no pending migrations; the production PWA build passed; **42 desktop/mobile browser journeys** passed with three workers and a 120-second per-test limit.
