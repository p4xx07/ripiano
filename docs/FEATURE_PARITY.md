# Paperless-ngx feature parity contract

Baseline: Paperless-ngx **v3.4.2**, released 2026-11-03. Ripiano is independent; this table defines behavior to preserve, not code to copy. Product improvements are defined in [PRODUCT_SPEC.md](PRODUCT_SPEC.md). The implementation must expand each row into API and end-to-end scenarios before marking it complete. A later Paperless release does not silently expand this pinned baseline.

Milestones: **R1** = safe daily archive; **R2** = full daily workflow and physical filing; **R3** = advanced management and integrations; **R4** = verified parity. R4 requires every row below, including optional features when explicitly enabled. Earlier releases may be useful without claiming full parity.

| Capability to preserve | Ripiano behavior / improvement | Target gate |
| --- | --- | --- |
| Web upload, drag-and-drop, consume folder, scanner imports, API upload | All channels reach the same durable ingestion pipeline; PWA and Android capture add simpler mobile paths | R1-R2 |
| Additional external inputs | Optional Telegram private-chat bot first; future S3 and Google Drive adapters use the same durable ingestion contract | R1-R3 |
| Incoming email accounts and filtering rules, including OAuth-capable providers | Import attachments with source metadata; email configuration lives in Integrations. IMAP accounts (password or Gmail/Outlook OAuth) and ordered rules with sender/subject/text/file-name/age filters, mark-read/flag/move actions, and tag/sender/type assignment are implemented; imported documents show the sender, subject, and mailbox. Ripiano never deletes mail. Processing whole .eml messages as documents remains open. | R3 |
| PDF, image, Office, and email file processing through optional converters | Preserve originals; produce searchable previews/archive versions where supported; show unsupported-format errors. DOCX/XLSX/PPTX, legacy DOC/XLS/PPT, OpenDocument ODT/ODS/ODP, RTF, and EML intake with private conversion are implemented; emails render from escaped text without remote content. Outlook .msg is implemented too: it is read locally with olefile (subject, sender, date, text, attachment names) and rendered like an .eml. | R1-R3 |
| OCR, selectable text, PDF/A, language settings, reprocessing | Local default; retry/reprocess without losing originals; compare OCR engines on actual scans | R1-R3 |
| Barcode/QR extraction, ASN detection, tag barcodes, split pages | Support documented paper scan workflows; physical-copy stickers add a separate stable identity. Local QR/1D barcode reading is implemented: PATCHT separator sheets split PDFs while the full scan is kept as a hidden source, ASN codes set a per-owner unique archive number (editable and searchable as `asn:`), and TAG: codes add existing tags. Configurable barcode-to-tag mapping rules and Paperless-style ASN-only document separation remain open. | R2-R3 |
| Tags, nested tags, correspondents, document types, storage paths, dates | Keep all metadata fields; create and move nested tags without cycles, and let parent Library filters include descendants; replace manual filing with suggestions and exception review. A disposable NAS year/tag browse copy exists. User-defined storage paths (templates with {correspondent}, {document_type}, {year}, {month}, {day}, {title}, {asn}, {tag}, {source}, and added-date placeholders) are chosen per document and lay out the browse copy; managed originals never move. | R1-R2 |
| Typed custom fields and document links | Create/edit/filter/search fields and links with permissions; preview and atomically convert compatible field values before a type change | R3 |
| Exact, fuzzy, rule-based, and learned matching; suggestions | Rules plus local pretrained model and correction examples; explain why suggestions appear. Optional example suggestions exist: the document dialog offers tags, senders, and types from the owner's manually filed similar documents, showing the example and its distinctive shared words; tapping a suggestion saves that field immediately while other draft edits still require Save changes. Tag, sender, and type rules match by exact phrase, any word, all words, similar spelling (fuzzy), or regular expression; regex search runs with a 0.25 s timeout over at most 100k characters, and fuzzy rules have at most 6 words. A calibrated learned classifier remains open. | R2-R3 |
| Optional AI suggestions, similarity search, document chat | Opt-in provider selection, including local endpoints; show when content would leave the NAS. Implemented: local "similar documents" (word-overlap similarity, with exact and likely duplicates flagged) without any model or external call. AI suggestions and document chat remain open | R3-R4 |
| Full-text search, field syntax, snippets, filters, sort, saved views | Search-first Library with simple filters and a power-user query mode; saved collections. `is:tagged` and `is:untagged` narrow results without creating a mandatory filing queue; Overview links directly to untagged documents. A saved Paper copy filter finds documents with a registered physical copy (including missing copies) or those kept only digitally. | R1-R4 |
| Duplicate detection and duplicate review | Exact/likely duplicate view; never silently throw away a captured original. Exact copies are flagged at upload and reviewed in Inbox; likely duplicates (≥85% word similarity) are flagged in each document's Similar documents | R2-R3 |
| Preview, original/archive download, notes, document history | Show common actions first; retain underlying versions and audit events | R1-R3 |
| File versions and merge-as-versions | Root metadata with version-specific file/text; explicit selection and history. Implemented: uploading a file or editing pages adds a version; earlier files stay downloadable, can be made current again, are included in document exports, and are removed only by permanent deletion. Combining existing separate documents as versions of one root remains open. | R3 |
| PDF rotate, split, merge, reorder, delete pages | Warn when an edit changes an original or invalidates a digital signature. Implemented: rotate, remove, and reorder pages save a new version (the previous file is kept); split pages into new documents; merge selected documents into a new PDF; digitally signed PDFs need explicit consent and keep the signed file as an older version. | R3 |
| Bulk edits, retagging, reprocessing, trash/restore, and opt-in retention | Preview and undo where possible; background job status for long actions | R2-R3 |
| Workflows: consume/add/update/scheduled triggers, filters, assignment/removal, email, webhook, password removal, AI actions | Guided recipes plus full advanced editor; deterministic execution and visible run history. Implemented: added, updated, and scheduled (days after a date) triggers; source, file-name, text, tag, sender, and type conditions; add/remove tags, set sender/type (never over manual choices), needs-action, note, webhook (metadata only), and SMTP email with optional attachment; once-per-document runs with a visible history. Password removal and AI actions remain open. | R3-R4 |
| Users, groups, object permissions, ownership, 2FA, OIDC/remote auth where applicable | Same access behavior across PWA, Android, REST, and MCP; agent grants are additional restrictions. Implemented: named MCP grants with separate search, OCR-text, tag, and sender/type scopes; the latter respects human/input-rule choices and records model origin. TOTP two-step sign-in has hashed single-use recovery codes, replay protection, and lockout. The Android client signs in through its embedded web app, so it uses the same code prompt; real-device validation is still pending. Groups, per-object permissions, and OIDC remain open. | R1-R4 |
| Share links, expiring links, bundles, email sending | Off by default; original-file links expire and can be revoked. Implemented: bundles share selected originals as one expiring, revocable, checksum-verified ZIP link, and documents can be emailed (original or searchable PDF) through configured SMTP with an hourly limit and send history. New versions revoke links and bundles | R3 |
| REST API, API tokens, documented schema, task/status endpoints | Versioned API and OpenAPI, with permission parity and compatibility tests. Implemented: personal API tokens (hashed, expiring, revocable, last-used tracking; no access to sign-in or security endpoints) and a generated OpenAPI 3.1 outline at `/api/schema.json` covering every route, method, and path parameter. Request and response body schemas and a versioned compatibility suite remain open. | R1-R4 |
| Dashboard, statistics, saved views, system monitoring and task controls | Home shows useful work without setup; advanced monitoring stays available. Implemented: an Overview with document, storage, follow-up, and processing totals; a "needs a look" list (unreadable, overdue, duplicates, mailbox errors, failed workflow runs); a 12-month intake chart with a table view; type, tag, and source breakdowns; and backup, mailbox, and workflow health. The archive owner also sees OCR and maintenance queue depth. Queued backups and NAS browse copies can be cancelled; failed or cancelled runs can be retried as a linked new run. Controls for other background jobs remain open. | R2-R4 |
| Export/import, maintenance, index rebuild, backup/restore | Open manifest and originals in single-document and selected-document exports; scheduled verified snapshots to mounted volume. Implemented: `export_archive` writes every account, record, original, older version, and searchable PDF with checksums to a portable folder, and `import_archive` loads it into an empty instance with all IDs and checksum verification. The search index needs no rebuild, because search runs in PostgreSQL. | R1-R4 |
| Search, metadata, and interface localization | Italian and English at minimum; no hard-coded text in components | R2-R4 |
| Keyboard shortcuts and accessible desktop interaction | Common actions and search are keyboard operable; mobile has touch-sized controls | R2-R4 |

## Additional Ripiano capabilities

These are not substitutes for parity rows: physical-copy hierarchy, printable document/container stickers, movement history, location contents that separate present copies from those reported missing, exception-only Inbox, first-class Needs action/reminders, installable iOS/Android PWA, Android native scanner, named per-agent MCP grants, optional daily local-PC worker, and scheduled backups visible in the app.

## Evidence required at R4

- Freeze and archive the upstream v3.4.2 documentation/API schema used for comparison; identify any capability missing from this initial table and add a row.
- For each row: automated API test where feasible and a real UI scenario for user-facing behavior. Record intentional behavioral changes with rationale.
- Cross-client parity check: a feature exposed in PWA must be available in the Android client, except that Android may add native capture behavior. Admin tools may use a responsive web view inside the client.
- Permission matrix tests for human users and at least two agents with different scopes and document filters.
- Representative Italian/English files, mixed document formats, duplicate scans, barcode sheets, signed PDFs, email attachments, and restore snapshots.
- No release is labelled Paperless feature-complete until every row is verified, not merely implemented in a hidden API.
