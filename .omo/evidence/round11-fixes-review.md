## Judge 2 findings (API)

Scope: judge 2 M1 and M2, and the API side of judge 3 L3 and L7. No file under `apps/web/` was changed.

- **M1 (no warning when the OCR worker is down): fixed (API).** Every Celery worker starts a small daemon thread in its main process on `worker_ready` (`ripiano/celery.py`, `archive/processing_status.py` `WorkerBeat`). Every 30 s it writes `WorkerHeartbeat(queue, beat_at=Now())` with the database clock for each queue it consumes, and it touches `/tmp/ripiano-worker-alive`. The API judges freshness by the database clock: a beat within ±2 min counts as running. `/api/jobs` and `/api/overview` (`health.processing`) return the same object: `{"pending", "processing", "waiting_since", "worker": {"running", "last_seen"}, "problem"}`. `problem` is `worker_not_running` (documents have waited more than 2 min and the OCR worker has not reported for 2 min) or `queue_unavailable` (a pending document was never handed to the queue server for more than 2 min). For the archive owner, the overview also returns `health.maintenance_worker`. In `deploy/docker-compose.yaml` and `compose.yaml`, `worker` and `maintenance_worker` gain a shell healthcheck (`find` on the file's age, every 60 s; no Python start-up). No new process and no new dependency.
- **M2 (duplicate OCR messages): fixed.** New `Document.queued_at` (migration 0065). Every place that queues OCR now calls `tasks.queue_document()`, which sends the message and then marks the document. A worker taking the document clears the mark, as do Retry, a new version, a stalled requeue, and a restore. The every-minute `requeue_pending_documents()` sends only documents never sent, and documents marked more than 5 min ago while the OCR queue is empty (the queue server lost them). The queue therefore never holds more than one message per waiting document. Round-9/10 recovery is unchanged: a stalled run is requeued after two passes and sent in the same pass, and a restore requeues processing documents and resends all waiting ones.
  - Extra bug found in the live check: `archive.tasks.reconcile_backup_runs` had no route, so every 5 min it landed in the OCR queue (the 6th message in the first live run). It is now routed to `maintenance`, and a test asserts that every scheduled task uses the maintenance queue.
- **L3 (counts disagree): fixed (API).** Background jobs now leaves out hidden split sources, like the Overview. Both endpoints return identical `pending` and `processing` counts (the overview `documents` also gains `pending` and `processing`; `waiting` is unchanged).
- **L7 ("Processing" for pending documents): API part done; the web part is still needed.** Each `/api/jobs` `documents_waiting` item gains `state`: `processing`, `stalled`, `queued`, `waiting_for_worker`, or `waiting_for_queue`. `since` for a pending item now uses the queue time. Document `status` stays `pending` or `processing` as before.

**Web changes needed (not made; apps/web is owned by another agent):**
1. Overview "Needs a look" (and the Background jobs header): when `health.processing.problem` (or `jobs.processing.problem`) is `worker_not_running`, show e.g. "Documents are waiting since {waiting_since}: the text-recognition worker is not running (last seen {worker.last_seen}). Start the worker container again." When it is `queue_unavailable`, show "Documents are waiting since {waiting_since}: the queue server cannot be reached."
2. Background jobs row: use `item.state`. `queued` → "Queued since…"; `waiting_for_worker` → "Waiting: no worker is running"; `waiting_for_queue` → "Waiting for the queue server"; `processing` and `stalled` as today. Do not show "will be tried again by itself" unless the state is `stalled` and `processing.worker.running` is true.
3. Overview tile: use `documents.pending` and `documents.processing` (or `health.processing`) so the Overview and Background jobs show the same numbers; `documents_waiting.total` now equals `documents.waiting`.
4. Library and document badges: show `pending` as "Waiting" (or "Queued"), not "Processing".
5. Optional: show `health.maintenance_worker.running === false` to the owner (backups and checks are not running).
